Best Model for Everything? Routing Work to Cheaper Tiers

July 2026 · 6 task archetypes × 3 scored tiers, blind-judged · routing landscape adversarially sourced

The maintainer runs 100% of tokens on the two most expensive Claude models. Commercial routers promise 20–98% savings; independent benchmarks say most routers can't beat simple baselines. We tested which of his real task shapes actually survive a downgrade, whether a knowledge file can change an orchestrator's delegation choices, and where routing genuinely doesn't belong. Tokens first; dollars are API-equivalent counterfactuals.

Baseline: the monoculture

From the mined 40-day dataset (see Token Economics): every one of 3,360 requests ran on Fable 5 or Opus 4.8. Zero Sonnet, zero Haiku. And because spend concentrates in a few marathon sessions (top 5 = 69%), the routing question is not "use a small model for small sessions" — it's "which phases inside big sessions can subagents run on cheaper tiers."

Delegation has a fixed cost that gates this: tonight's live measurements put research-grade subagents at a ~16–30k-token spawn floor, median ≈58k tokens each. Routing pays when the delegated bulk clears that floor — the standing ≳30k rule survives another night of data.

Pattern worth noticing

The independent benchmark's core finding — routers over-rely on the strongest model — is the maintainer's own usage pattern, automated. The failure mode of naive routing is the human default too.

Experiment: which task shapes survive a downgrade

Six archetype tasks distilled from real session history, identical prompts across claude-haiku-4-5 / claude-sonnet-5 / claude-opus-4-8 (scored) + Fable 5 (unscored reference), graded blind by a judge outside the scored set against pre-registered rubrics. One trial per cell — single observations, not capability claims. Two findings bigger than the table

(1) The routing line sits lower than the maintainer's habits assume: lookup-shaped and rule-shaped work survived Haiku untouched in this trial, and the one wrong answer in extraction came from the expensive arm. (2) Verbosity is a hidden tax: for the same 6 extraction answers, Haiku emitted 453 output tokens where Opus emitted 63 — unit price is not per-task price. Route by task shape, then check output discipline.

Experiment: can a knowledge file change delegation?

Learned routing from an agent's own experience logs is essentially unshipped territory (two 2026 surveys — routing-side and memory-side — have zero coverage of the pattern; no framework implements it). Before proposing it as a distill feature, the cheap question: given the same 5-item task list, does an orchestrator with a routing knowledge file choose differently than one without? Per the adversarial review, success means matching E1's ground truth — not parroting the injected file — and the no-file arm's natural behavior is the headline.

Same orchestrator, same 5 tasks, ± routing knowledge file (N=2 per arm) The no-file arm is the story
Arm B — no routing file
Routes near-optimally unaided, both reps: Haiku for the transform, extraction and sweep; Opus for debugging and methodology review. Rationales are sound ("no judgment needed, buy the cheapest tokens"; "a missed confound is far more expensive than the model").
Arm A — with routing file
Same choices, now citing the E1 evidence; the file's one visible effect was shifting a borderline call (CSS diagnosis) toward the cheaper Sonnet floor in one rep. It also imported the verbosity warning ("cap output length").
The finding underneath

Stated routing judgment was already near-perfect — yet 40 days of revealed behavior is a 100% frontier monoculture with zero delegated cheap-tier calls. The binding constraint is not knowledge; it's that the routing decision never gets asked in real sessions. This is the execution gap again (see Token Economics, friction section): prose rules don't change in-flight habits — structure does. The actionable version of "distill learns routing" is therefore less about richer rules and more about installing the decision point: subagent definitions with model: defaults, and a delegation checkpoint in heavy-session workflows.

The whitespace: distill as a routing-rule learner

What the literature calls "memory-augmented routing" exists as three thin papers and no products. Distill already has the full loop the papers lack: session retrospectives that notice which delegations succeeded on which tier (signal), a knowledge store with confidence/staleness metadata (memory), and a session-start monitor that injects the rules where delegation decisions happen (retrieval). The proposal that survives tonight's evidence:

  1. [ROUTE] markers in ops knowledge — per task-shape entries with the E1-style evidence attached, encoded by /distill when a session produces a clean routing observation ("the Haiku sweep was verbatim-correct", "the Sonnet refactor missed the invariant").
  2. Confidence discipline — routing rules enter as [PROVISIONAL], harden only on repeated confirmation, and carry staleness thresholds (models change quarterly; a routing rule about claude-sonnet-5 must expire).
  3. Trade-off knob, not default — per this project's release rule: routing changes agent behavior, so it ships as an explicit opt-in with the consequence spelled out (cheaper bulk phases; occasional tier misjudgment costs a redo).

Playbook for the "best model for everything" user

  1. Keep judgment on the frontier. The data says the expensive habit is right where it matters: design review, debugging with interacting causes, synthesis. That's also where the money already goes ($ concentration in marathon creative sessions).
  2. Route the bulk phases of big sessions — transforms, extraction, sweeps — to Haiku-tier subagents when the avoided bulk clears the ~30k-token spawn floor. Native model: frontmatter covers this; no external router earns its fee here.
  3. Mind the two hidden taxes: cheap-model verbosity (3–7× output for identical answers) and mid-session model switches breaking the prompt cache (subagents with their own model avoid this; /model flips don't).
  4. Order of operations stands: context hygiene first (~85% of cost), delegation second, tier routing third — routing optimizes the slice, hygiene optimizes the pie.
  5. Let distill learn the routing table case-by-case — the [ROUTE] proposal above — instead of trusting any router's marketing. The independent evidence says routers mostly don't beat "always strongest"; a personal, evidence-backed routing memory is the version of routing that can.

Limitations

  1. n=1 per E1 cell; single night, single machine, subscription metering. Findings are directions with magnitudes, not measurements of capability.
  2. Model set is Claude-only and July-2026-specific; every tier verdict carries an expiry date by construction.
  3. The judge is an LLM (pinned outside the scored set, blinded, rubric-gated) — and it still surfaced one authored-rubric error, which says something about rubric authorship as the real bottleneck.
  4. E2 tests choice behavior, not end-to-end outcome quality; the outcome test is a future run with the routing file live in real sessions.
  5. The incumbent's author authored the study; designs were pre-registered and adversarially reviewed before running, and contested cells are reported as contested rather than resolved in the house's favor.
