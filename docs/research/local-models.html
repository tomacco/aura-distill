Can a Local Model Do the Distilling?

September 2026 · live study, updated as runs land · Apple M5 Pro 48 GB → 16 GB targets

Distillation's first stage reads a session transcript and extracts the signals worth remembering. The routing directive already forbids frontier models there. This study asks how much further down it goes — all the way to an open-weights model on the user's own machine, at zero API cost. The answer splits sharply on memory: at 48 GB a local model beats the hosted cheap tier outright; at 16 GB, the configuration most users actually have, nothing tested is usable. Results were published here as each run landed, not held back until the end.

Current status · updated 2026-09-23 · replicated on real sessions

Replicated. The headline comparison now holds across three real sessions, two harness formats and 8.6k–63.3k tokens: the local model beat the hosted cheap tier on every transcript and every metric, and fabricated nothing in three runs. The answer splits on memory, and the cliff is between 16 GB and 32 GB. At 48 GB a local 27B reached 81% of the Opus reference at $0 — better than both hosted cheap tiers on faithfulness. Quantising that same model to 4-bit keeps 77% for half the memory, so capacity matters far more than precision. But even 4-bit needs 17.8 GB resident before a single token of transcript, which rules out 24 GB machines at default settings and 16 GB machines entirely. At 16 GB the best candidate reached 41%, and the failure is misattribution — scrambling who did what — the one error class this pipeline cannot absorb.

The question, and why the cheap tier isn't obviously the answer

The /distill pipeline's Step 1 — signal harvest — reads a conversation and emits a five-part structured summary: failures and friction, corrections the user made, observations about how the user works, the origin of each decision, and session metadata. It is extraction, not judgment about code, so the routing study assigns it to the cheap tier.

Two things make that worth re-testing. First, the stage runs in the background for the planned auto-distiller, so latency barely matters and quality does. Second, a model that runs locally costs nothing per token — which makes it the true floor of the cheap tier, below Haiku, if its output is good enough.

"Good enough" is the hard part. A harvest that invents a fact does not merely score badly; it writes a false belief about the user into a knowledge base that later sessions treat as authoritative. So this study measures two different things and refuses to collapse them: how much the model finds, and how much of what it says is true.

How a model is scored against Opus

One real Claude Code session is rendered to plain text, deterministically. Every model — hosted or local — receives byte-identical input and the same prompt, lifted from the shipped distill.md. Opus 5's harvest is the reference. Then a blind judge, never told which system produced which output, does two passes:

Recall
The reference is decomposed into 116 atomic claims. Each is marked present, partial or absent in the candidate. How much did it find?
Grounding
The candidate is decomposed into its own claims, each checked against the transcript: grounded, distorted, or fabricated. Is what it says true?
The ceiling is not 100%

Opus re-run on the identical prompt recalls only 91.8% of its own first answer. Two runs of the same frontier model disagree about one claim in twelve. So 0.918 — not 1.0 — is what "100% of Opus" means on this page; every percentage is normalised to it. Without that anchor, every model looks worse than it is, and the reader has no way to tell ordinary run-to-run variance from a real quality gap.

One correction is baked into the method. In the first pass each candidate was judged in a separate call, and the boundary between "distorted" and "fabricated" drifted between them — the same kind of note landed on different sides for different models. An independent reviewer caught it. A calibrated adjudication pass now pools every non-grounded claim from every candidate into one blind, shuffled call with a pinned rubric, so a single boundary applies to all of them. It moved 10 of 43 labels, and it changed a headline figure. Numbers below are post-adjudication.

Finding 1 — the hosted cheap tier fails on truth, not on coverage

Haiku's grounding of 0.552 means nearly half of everything it asserted was wrong in some way against the transcript, and one claim in ten had no referent there at all. The inventions were not random: they were attributions to the user. That the user knew a convention by heart. That the user accepted a proposal. That the user responded to something, when no such response exists in the session.

Why this is worse than a low score

The distillation process has an explicit anti-sycophancy rule — never encode comfort as truth. A model that invents user approval violates it in the one section where the error is unrecoverable: the user model. A wrong technical detail gets corrected the next time someone reads the file. A false belief about what the user knows and wants shapes every future session silently.

Finding 2 — the local model beat both hosted cheap tiers, for nothing

Qwen3.8-27B recalled more than Sonnet and far more than Haiku, with a grounding score above both, at zero marginal cost. It was not clean — it invented two assistant mental states, and it made the same category of error as the others, recasting the user's knowledge gaps as expertise. Sycophancy toward the user model is the shared weakness of every non-frontier model tested, local ones included. If a local model ships, that section needs a guard.

Where it loses ground is precision about numbers: it drops token counts, dollar figures and file counts, and is weakest exactly where the reference is densest. Structurally it was flawless — five sections in order, every decision carrying an origin label — and the judge rated its origin-labelling discipline better than the reference's.

Finding 3 — the cost is entirely time, and thinking is most of it

30.6 minutes against Opus's 71 seconds. Prompt processing was fine at 342 tokens/s; generation ran at 8.8 tokens/s because a dense 27B at 8-bit is memory-bandwidth bound. Two-thirds of everything it generated was reasoning the user never sees — 42,654 characters of thinking before the first line of the answer. That makes the thinking budget, not the model size, the first lever to pull.

At 30 minutes per transcript a nightly background pass over undistilled sessions is unremarkable. An interactive /distill at that latency is not shippable.

A measurement worth stealing

A two-character prompt through the same headless flags costs 8,302 tokens — about 7.5k of which is pure harness floor carried into every call, before any content. --tools "" and --tools none measure identically. Any token accounting that ignores that floor is wrong by roughly the size of a small transcript.

Experiment 2 · 16 GB complete

Experiment 1 measured a ceiling on a developer machine. This one measures what users actually get. On 16 GB of unified memory the OS and open applications leave roughly 8–10 GB for weights and KV cache, which rules out everything tested above.

One variable at a time, deliberately

The obvious move is to change thinking, architecture and quantization together and jump straight to a 16 GB candidate. That would make the result uninterpretable: whichever changes first moves the number, and the others get measured against a different baseline. Thinking-off on the already-characterised 27B runs first for exactly that reason, even though it costs an extra run.

Run 1 — thinking off: 4.8× faster, 9 points cheaper in recall

Same model, same weights, same transcript, same prompt, same judge. The only change is that the model no longer reasons before answering.

Thinking buys coverage, not honesty

The entire cost of switching it off lands on recall — the model finds less. Grounding moves by about one percentage point and fabrications go down, not up. That separates two things it would have been easy to conflate: reasoning tokens help a model notice more of what happened, and do essentially nothing for whether what it reports is true. For a background job that can afford thirty minutes, leave thinking on. For anything latency-bound, switching it off is a coverage trade, not an integrity one.

Both runs still generate at 8.8 tokens/s — the speedup is entirely fewer tokens, not faster ones, which confirms the bandwidth bound rather than working around it. Peak memory was unchanged at 32.3 GB, so this run does nothing for the 16 GB problem on its own; it isolates a lever before the memory-constrained candidates move three variables at once.

Against the prediction. Thinking-off was called as the biggest single speed lever available, and at 4.8× that held. The open question was whether removing deliberation would worsen the user-model errors or reduce them: the answer is neither to any meaningful degree. That question is now closed, and closing it cost one run.

The verdict at 16 GB

Every candidate that fits collapses to 0.59–0.65 grounding — a third of what they assert does not survive a check against the transcript. The best of them recalls 41% of the reference against the 27B's 81%. Halving the memory did not halve the quality; it removed most of it. On this evidence there is no 16 GB configuration worth shipping for this stage today.

The failure is misattribution, not invention

The study-wide adjudication makes the shape precise. Outright fabrication is rare in the small models — 0, 1 and 0 claims. What they do instead is distort: 13, 15 and 11 claims each carry a real referent stated wrongly. Overwhelmingly, that means swapping who did what. The 9B credited the assistant's proposals to the user and read impatience into a go-ahead the assistant had itself requested. gpt-oss-20b, in the judge's words, "repeatedly credit[s] the user with facts, explanations and directives that were the assistant's own", and invented user emotions and a session duration.

For most summarisation tasks that would be a small error. For this one it is the worst possible error: sections C and D exist precisely to record who decided what and why. A harvest that scrambles agency writes a false model of the user into a knowledge base that later sessions treat as settled fact.

Gemma 4 could not be run at all

Neither Gemma 4 size that fits 16 GB is loadable by any released mlx-lm. The 12B checkpoints declare model type gemma4_unified, which 0.31.3 — the newest on PyPI — does not implement; E4B fails with a 126-parameter mismatch against the gemma4 implementation that does exist. The 26B-A4B MoE that would load is 15.6 GB, too large for the target. Gemma 3 12B stands in, and is labelled a substitute rather than a Gemma 4 result.

Tooling support gates availability, independently of capability

A model you cannot load is not a candidate, however good its benchmarks are. For a hosted API this failure mode does not exist. For a local-model strategy it is a first-class risk, and it argues for treating runtime support as a selection criterion rather than an implementation detail — especially for a feature shipped to users who will not debug a quantisation loader.

What the review cost, and what it bought

Two of the three blocking findings changed numbers that had already been published. The reviewer predicted the corrected fabrication rate — ~2 of 58 claims — before the adjudication pass was written, and the pass returned exactly that. The value of a reviewer with no authorship context is not that it finds typos; it is that it does not know which claims you are attached to.

Capacity beats precision, and it is not close

Halving precision on a 27B cost 4 points. Dropping to a 9B at the same precision cost 40. Both moves free comparable memory. If you have to shrink a local model to fit a machine, quantise the big one rather than reach for a small one — and the 4-bit run was also cleaner than the 8-bit on fabrication, not worse.

The honest 24 GB verdict

A 24 GB Mac cannot run this model as shipped. It can run it if the owner raises iogpu.wired_limit_mb — a system-level change made with sudo sysctl, lost on reboot unless persisted, and not something to put in a feature's setup instructions for general users. Even then the transcript length is capped well below the longest real sessions in the corpus. The practical floor for this stage is 32 GB.

Measured on a 48 GB machine. The memory figures are real; the 16/24 GB verdicts are those figures compared against those machines' documented limits, not runs on such machines. Anyone with a 24 GB Mac who wants to falsify this only needs to run the harness on one.

The claim that argued against the routing directive is no longer n = 1

A local open-weights model running for free on the developer's own machine produced a more faithful harvest than the hosted cheap tier on three of three real sessions, across two different CLI formats, with zero fabricated claims against Haiku's eight. The original transcript turns out to have been the local model's worst showing, not a flattering one.

The ceiling is a property of the transcript

Opus's self-agreement varied — 0.918, 0.930, 0.869 — and fell on the longest session. Any study reporting “% of a reference model” without measuring that per input is quietly mixing run-to-run variance into its quality gaps.

An observation, not yet a finding

The local model improved as transcripts got longer (77% → 87% → 96%) while the ceiling fell. One reading is that on long sessions every model converges on the main arc, and the fine detail Opus captures inconsistently is exactly where disagreement lives. Three points do not support asserting that. What it does settle is that the “long transcripts unaddressed” caveat this study carried from the start pointed the wrong way: length was not where the local model fell apart.

Two constraints on this replication, both real. Only the local model and Haiku were re-run — the 16 GB candidates and the 8-bit variant were not, because their verdicts were already unambiguous and re-running a clear negative buys little. And the corpus excludes one session containing employer-internal infrastructure detail, at its owner's direction.

There is a real local option, and it needs 32 GB. On a machine that has it, a 27B does this stage better than the cheap hosted tier, for nothing. At 4-bit it keeps 77% of the reference, runs in under seven minutes and needs 18.9 GB — which is why 32 GB, not 24, is the floor.

There is no 16 GB or 24 GB option today. At 16 GB, a 40-point gap and grounding in the low 0.6s across three families. At 24 GB the quality is there but the memory is not, without a system-level change. The honest recommendation below 32 GB is a hosted mid-tier model, not a local one.

Haiku remains the most alarming row in the table, and it is hosted. Across three sessions it grounded a mean of 0.639 of its own claims and invented eight, against zero from the free local model. Cheapness bought neither speed nor safety here.

What would change the answer

Not a better 9B. The gap is too large for a model of that size to close by being slightly better. What could close it is changing the task: chunking a transcript so a small model judges one exchange at a time, where misattribution has far less room to occur, and where a wrong answer is cheap to discard. That is a different experiment, and this study does not test it.

Limitations read before citing

Still one run per model per transcript. The headline comparison — local versus hosted cheap tier — now has three transcripts behind it and survives on all three, so it no longer rests on a single measurement. Everything else on this page does: the 16 GB verdicts, the thinking-off result and the 8-bit/4-bit comparison were each measured once, on the original transcript. Treat those as provisional.

The judge and the reference are the same model family. Opus judges output that is scored against an Opus reference. Self-preference bias is plausible even with the judge blind to which system produced what, and it would inflate the ceiling row while deflating everyone else. The adjudication pass fixed the consistency of the fabrication boundary; it does nothing about this.

A rendered transcript is a proxy. Today's /distill harvests from live conversation context. This study feeds a text rendering with tool results truncated. That proxy is right for the planned background auto-distiller, which will also cold-read transcripts from disk, and wrong for measuring the in-session command as it ships now.

Only the harvest stage. Encoding — the step that actually writes to the knowledge base — is a harder, higher-stakes job, and nothing here says anything about running that locally.

Long sessions are unaddressed. The test transcript is 13.6k tokens and fits trivially. A 100k-token session's KV cache will not fit on a 16 GB machine at all; chunking and merging is a separate design problem that has not been measured.

This page does not update the routing playbook. The model routing study currently recommends Haiku-tier for extraction, which finding 1 is evidence against. One transcript is not enough to overturn a published recommendation, so the tension is tracked as an open issue rather than acted on.

What is not published. The session transcript, the five models' harvest outputs and the reference claim texts stay private — they are a real session and five models' written observations about a real person. All measurements, all tooling and the judges' evaluative notes are public, and the harness regenerates the rest from any local transcript.
