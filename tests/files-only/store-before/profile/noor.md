## Expertise Map

- Distributed systems: deep — designs the retry and idempotency layers without prompting
- Data platform: working — learning lakehouse tooling through the Atlas migration
- Frontend: curious — asks about component structure, defers on styling

## Communication Style

- Terse in ops mode ("ship it", "rollback"), discursive when changing process.
- Identifies things by quoting content, not by path or index. Resolve by content match.
- "done?" wants evidence: the curl output, the test run, the dashboard screenshot.

## Thinking Patterns

- Principle-first. Starts from "the issue is consistency", then finds the endpoint.
- Wants adversarial pushback on architecture; "convince me" is an invitation, not resistance.

## Trust Topology

- Delegates freely: test scaffolding, migration scripts, documentation drafts.
- Verifies before approving: anything that touches billing or retention (legal exposure).
- Retains completely: public communication about incidents.
